=== Данные

include::6.1@webclient:layouts:partial$properties.adoc[tags=extendedDataSource]

include::6.1@webclient:layouts:partial$properties.adoc[tags=dataSource]

Ссылка на списанный в дело документ всегда будет добавлена в дело. Если в свойствах ЭУ `_Дело_` указать источник данных, в карточку "Документ" будет дополнительно добавлена ссылка на карточку "Дело", в которое документ был списан. Если не указан "Источник данных", ссылка на "Дело" добавлена не будет.

Разметка настраивается в зависимости от требований и необходимости второй ссылки.

==== Поле данных

Поле карточки, содержащее ссылку на карточку _Архивное дело_.

Для отображения ссылки в карточке дела сохраняются следующие поля карточки документа: _RefDocument_, _Digest_ и _Registered_ (необходима привязка к полю _RefCardID_ -- _Архивное дело_).

include::6.1@webclient:layouts:partial$properties.adoc[tags=editOperation]

Если в настройках ЭУ `_Дело_` раздел Данные не заполнен, то при добавлении документа в дело, информация о списанном документе появляется в карточке дела, а ссылка на дело в карточку документа не добавляется.

[#mode]
==== Режим списания

В зависимости от указанного в свойстве значения при выборе дела выполняются проверки:

* Если выбрано значение *_Списание_*, при выборе дела выполняются все проверки, настроенные при выборе дела.
* Если выбрано значение *_Выбор_*, при выборе дела не выполняются никакие проверки, настроенные при выборе дела.

=== События

[#before-auto]
==== До автосписания

Вызывается перед автосписанием.

.Поиск подходящей для списания РК дела осуществляется по следующим параметрам:
* Ответственное подразделение (в списываемой РК документа поле должно быть привязано к метаданным `General information\ResponsDepartment`).
* Год даты регистрации (в карточке документа поле должно быть привязано к метаданным `General information\RegDate`).
* Вид документа (в списываемой карточке документам вид документа `System Properties\kind`).
* Другие дополнительные параметры `General information\AdditionalParameter` (необходим для расширения модели поиска).

Для автосписания карточки документа в подходящую карточку дела в карточке дела ЭУ `_Список видов документов_` должен быть привязан к метаданным `TypesDocumentForStorage\Kind`.

[#algo]
===== Алгоритм поиска карточки дела для списания

. Получается из РК документа ответственное подразделение (`ResponsDepartment`), год даты регистрации (`RegDate`), вид документа (`Kind`);
. Осуществляется поиск РК дела, у которой:
+
.. В поле _Подразделение_ значение равно "Ответственному подразделению" из списываемой РК документа.
.. РК дела входит в состав номенклатуры дела того года, который равен полученному из списываемой РК документа Году даты регистрации.
.. В поле _Список видов документов_ РК дела указан вид списываемой РК документа.
.. В РК дела указан необходимый для списания дополнительный параметр из списываемой РК документа (`AdditionalParameter`).
. Полученный список РК дел фильтруется дополнительно по следующим параметрам:
+
.. Состояние карточки дела -- `Открыто` +
И +
.. Разрешить списание в закрытое дело -- `*Нет*` +
ИЛИ +
.. Состояние карточки дела -- `Закрыто` +
И +
.. Разрешить списание в закрытое дело -- `*Да*`
+
. Если найдена одна РК дела найдена, то получается её GUID и записывается в поле _Дело_ РК документа +
+
. Если найдено больше одной РК дела, то:
+
.. Получается GUID и заголовки этих РК дел.
.. Формируется список, который выводится пользователю с сообщением: `Найдено более одного подходящего дела для списания. Пожалуйста, выберите дело из списка для списания документа` и кнопками *ОК* и *ОТМЕНА*.
.. При нажатии *ОК* выбранное пользователем дело из списка записывается в поле _Дело_ РК документа.
.. При нажатии *ОТМЕНА* остается возможность перейти в поле _Дело_, открыть дерево номенклатуры и выбрать дело.
. Если РК дела не найдена:
+
.. По справочнику сотрудников по цепочке вверх находятся родительские подразделения _Ответственного подразделения_ до организации.
.. По каждому полученному родительскому подразделению повторяются шаги 2-5.
.. Если РК дела не найдена, то:
+
... У РК раздела, у которой значение в поле _Подразделение_ равно ответственному подразделению из списываемой РК дела, осуществляется поиск родительской РК раздела по полю _Родительский раздел_. Просматриваются все родительские разделы РК, пока не будет получена РК раздела, у которой значение поля _Подразделение_ --  строка типа _Организация_. Копируется GUID этой РК.
... Далее осуществляется поиск РК разделов, у которых в поле _Родительский раздел_ указан GUID РК раздела, у которой значение поля _Подразделение_ -- строка типа _Организация_.
... Осуществляется поиск по цепочке вниз дочерних РК разделов, у которых установлен признак _Документы организации_.
... По полученным РК разделам осуществляется поиск РК дел, которые соответствуют условиям из шага 2-3.
... Далее повторяются шаги 4-5.
... Если не найдено ни одной подходящей РК дела, то выводится сообщение `Дело для списания не найдено. Укажите дело для списания вручную` с кнопками *ОК* и *ОТМЕНА*.
... После закрытия окна любой из кнопок, остается возможность перейти в поле _Дело_, открыть дерево номенклатуры и выбрать дело.
