[#mancons]
== Конфигурация Сервера приложений из {of-mc}

// tag::settings[]

[subs="specialchars,attributes,quotes"]
Чтобы настраивать Сервер приложений при помощи {of-mc}, необходимо убедиться, что конфигурационном файле {config} указаны минимальные настройки.

ifndef::installation[]
[WARNING]
====
include::6.1@platform:admin:partial$update.adoc[tags=priority]
====
endif::installation[]

. Откройте конфигурационный файл в любом текстовом редакторе (потребуются права суперпользователя/администратора) и убедитесь в корректности следующих параметров: menu:ServiceId[], menu:SettingsService[ConnectionString], menu:Kestrel[].
+
--
// tag::config[]
ifndef::installation[]
.Фрагмент конфигурационного файла `appsettings.json`:
[source,json]
----
{
  "DocsVision": {
    "ServiceId": "00000000-0000-0000-0000-000000000000", <.>
    "SettingsService": {
      "ConnectionString": "http://localhost:5200/api", <.>
      "ApiKey": "anything" <.>
    },
  },
  "AllowedHosts": "*",
  "Kestrel": { <.>
    "Endpoints": {
      "Http": {
        "Url": "http://*:5000"
      }
    }
  }
}
----
<.> `ServiceId` -- уникальный идентификатор данного экземпляра модуля, генерируется и записывается автоматически.
<.> `ConnectionString` -- полный адрес {of-sett-serv}.
<.> `ApiKey` -- API-ключ для подключения к {to-sett-serv}, можно оставить значение по умолчанию или изменить, главное условие, чтобы значения в конфигурации модулей {sett-serv} и {pl} были одинаковые. Адрес и API-ключ требуется указать, если планируется переходить в {mc} из карточек {wc}а и {wincl}а.
<.> Настройка защищённого (HTTPS) соединения с Сервером приложений для защиты конфиденциальных данных, см. подробнее xref:dv6@engineer:ROOT:https-connection.adoc[].

[#old-method]
== (Старый метод) Конфигурация модуля {pl} без {of-mc}

[subs="specialchars,attributes,quotes"]
Конфигурационный файл может быть изменён в любом текстовом редакторе, файл располагается по адресу {config-pl}. После сохранения изменений в конфигурационном файле обязяательно перезапустите службу Сервера приложений.

.Фрагмент конфигурационного файла `appsettings.json`:
[source,json]
----
{
  "DocsVision": {
    "Platform": {
      "Server": {
        "DefaultBaseName": "alias", <.>
        "LogFile": "/var/log/docsvision/dvappserver.log", <.>
        "WindowsSecurityServerName": "any.domain.com", <.>
        "Databases": {
          "alias": "CONNECTION-STRING"  <.>
        }
      }
    },
    "ServiceId": "00000000-0000-0000-0000-000000000000", <.>
    "SettingsService": {
      "ConnectionString": "ConnectAddress=http://settings.service.com:5200/api", <.>
      "ApiKey": "apikey-settingsservice" <.>
    },
    "Workflow": {
      "ApiKey": "api-key" <.>
    }
  },
  "Groups": {
    "DocsVision Administrators": [
      "domain\\account"
    ], <.>
    "DocsVision Security Administrators": [
      "domain\\account"
    ],
    "Docsvision Management Console Administrators": [
      "domain\\account"
    ]
  },
  "Ldap": { <.>
    "AuthType": "Basic", <.>
    "Credential": {
      "UserName": "account@domain.com", <.>
      "Password": "password" <.>
    }
  },
  "Catalogs": [
  <.>
  ],
  "DataProtectCertificateThumbprint": "thumbprint", <.>
  "SystemUserAccount": "account@domain.com", <.>
  "SystemUserPassword": "password", <.>
  "Logging": { <.>
    "LogLevel": {
      "Default": "Error"
    }
  }
}
----
<.> `DefaultBaseName` -- псевдоним базы данных. Должен совпадать с псевдонимом подключаемой базы в Консоли настройки. Можно заполнить заранее, или вернуться позже, после создания из Консоли управления.
<.> `LogFile` -- путь к файлу журнала сервера. Параметр необязательный, если он не указан, действует системная настройка по умолчанию.
<.> `WindowsSecurityServerName` -- необходимо указать имя любого компьютера в текущем домене Active Directory. Используется при получении списка доступных членов домена при настройке дискреционной безопасности в {wincl}е, РМА и DVExplorer.
<.> `alias` -- псевдоним используемой БД, для которой задаётся строка подключения. `CONNECTION-STRING` -- строка подключения, подробное описание строки подключения см. <<connection-string,ниже>>.
<.> `ServiceId` -- уникальный идентификатор данного экземпляра модуля, генерируется и записывается автоматически.
<.> `ConnectionString` -- полный адрес {of-sett-serv}. Если {sett-serv} ещё не установлен, адрес можно заполнить позднее.
<.> `SettingsService > ApiKey` -- используется для подключения серверного расширения {wf}. API-ключ для подключения к {to-sett-serv}, можно оставить значение по умолчанию или изменить, главное условие, чтобы значения в конфигурации модулей {sett-serv} и {pl} были одинаковые. Если модуль {wf} ещё не установлен, можно оставить значение по умолчанию или изменить, главное условие, чтобы значения в конфигурации модулей {pl} и {wf} были одинаковые.
<.> `Workflow > ApiKey` -- API-ключ для подключения к Workflow -- используется для подключения серверного расширения {wf}. Главное условие, чтобы значения в конфигурации модулей {pl} и {wf} были одинаковые.
<.> `Groups` -- эквивалент системных групп. Указанные в группах пользователи будут обладать соответствующими правами. Обратите внимание, что в группах массив строк, а не строка.
+
.Пользователь, выполняющий установку и настройку системы должен входить в группы:
* *{dv-admins-serv}* и *{dv-sec-admins-serv}* -- администраторы системы и администраторы безопасности системы.
* *{dv-web-admin-cns-admins-serv}*. Пользователи, входящие в эту группу, имеют право просматривать карточки сообщений в {of-mc}.
+
* Также через конфигурационный файл выполняется настройка клиентской части, см. подробнее xref:6.1@platform:console:config-client.adoc[].
+
<.> `Ldap` -- имя и пароль учётной записи, под которой процесс обращается к ActiveDirectory.
<.> `AuthType` -- тип аутентификации: `Basic` -- аутентификация через LDAP, `Oauth` -- аутентификация через ЕСИА или Azure.
<.> `UserName` -- логин пользователя модуля для аутентификации LDAP.
<.> `Password` -- пароль учётной записи пользователя для аутентификации LDAP в открытом или в зашифрованном виде, см. подробнее о шифровании в документации по установке системы, раздел "xref:dv6@engineer:ROOT:appendix/account-protection.adoc[]".
<.> `Catalogs` -- настройки доменных каталогов сервера {dv}, см. "xref:./config-domains.adoc[]".
<.> `DataProtectCertificateThumbprint` -- отпечаток закрытого ключа шифрования SHA1. +
Указывается без двоеточия, например, `D8602179888DC8402B393F11DCA16A3376DDF879`, см. подробнее в документации по установке системы, раздел "xref:dv6@engineer:ROOT:appendix/account-protection.adoc[]". +
Если шифровать пароль системной учётной записи не планируется, параметр можно удалить.
<.> `SystemUserAccount` -- имя системной учётной записи {dv}.
+
include::dv6@install-linux:ROOT:partial$excerpts.adoc[tags=system-accounts]
+
<.> `SystemUserPassword` -- пароль системной УЗ рекомендуется хранить в зашифрованном виде, см. подробнее в документации по установке системы, раздел "xref:dv6@engineer:ROOT:appendix/account-protection.adoc[]".
<.> `Logging` -- настройка упразднена, используйте параметр `LogFile` или настройте журналирование с помощью xref:6.1@platform:console:logs.adoc#file[NLog].

[#fs-config]
== (Старый метод) Конфигурация {of-fs} в конфигурационном файле

. Укажите существующую БД, заполнив строку подключения к БД в конфигурационном файле:
+
--
[source,json]
----
{
  "DocsVision": {
    "Server": {
      "Databases": {
        "alias": "Database-connection-string" <.>
      }
    }
  },
  "NLog": { <.>
  },
  "AllowedHosts": "*",
  "Kestrel": { <.>
  }
}
----
<.> `alias` -- <<connection-string,строка подключения>> к БД.
<.> `NLog` -- настройки жерналирования, см. "xref:console:logs.adoc#file[Журнал работы файлового сервиса]"
<.> `Kestrel` -- настройка доступа к Storage Server по HTTPS, см. подробнее xref:dv6@engineer:ROOT:https-connection.adoc[].
--
+
. После сохранения изменений в конфигурационном файле перезапустите службу {of-fs}.
