[#linux-update]
== Обновление модуля на сервере под управлением Linux

Если к новой версии модуля прилагается отдельная инструкция по обновлению, следуйте ей.

.Чтобы установить новую версию модуля:
. Создайте резервную копию БД.
// tag::main-update-process[]
. Если в БД {pgsql} используется pgAgent, остановите планировщик.
// . Остановите сервис `dvappserver` все сервисы {dv}. Также остановите экземпляры Службы {ws} и все сервисы в кластере {dv} или СУБП, если таковые используются.
. Обновите серверные компоненты на сервере Linux командой:
+
[tabs]
====
{os1}::
+
[source,subs=attributes]
----
sudo apt-get update
sudo apt-get install --only-upgrade docsvision-{update}*
----
ifndef::mancons[]
{os2}::
+
[source,subs=attributes]
----
sudo dnf makecache
sudo dnf update docsvision-{update}*
----

{os3}::
+
[source,subs=attributes]
----
sudo apt-get update
sudo apt-get install --only-upgrade=true docsvision-{update}*
----
endif::[]
ifdef::mancons[]
{os2}::
+
[source]
----
sudo dnf makecache
sudo dnf update docsvision-managementconsole* docsvision-settingsservice*
----
endif::[]
====
+
ifdef::is-service[]
. При обновлении сервера {dv} предыдущих версий под управлением {os1} будет предложено перезаписать текущий конфигурационный файл `appsettings.json`.
+
.Доступные варианты:
[%collapsible]
====
* Перезаписать текущий конфигурационный файл `appsettings.json`.
** Текущий файл будет перезаписан стандартным, все выполненные настройки будут сохранены в файле `appsettings.json.dpkg-old` (`appsettings.json.rpmsave` для {os3}), их необходимо будет перенести в {mc}.
+
[subs="specialchars,attributes,quotes"]
Начиная с НО 26.1, основным инструментом настройки системы является {mc}. Принимая решение заменить конфигурационный файл модулей {pl} ({sss-new}), {fs} ({fss-new}), {wc} ({wcs-new}), {wf} ({wfs-new}), {mc} ({wacss-new}), учитывайте, что существующие настройки будут заменены базовым набором параметров:
+
menu:ServiceId[]::
Уникальный идентификатор данного экземпляра модуля. Параметр задаётся автоматически при установке модуля.
menu:SettingsService[ConnectionString]::
Адрес подключения к хранилищу настроек. Параметр необходимо указать вручную.
menu:SettingsService[ApiKey]::
Ключ приложения для подключения к хранилищу настроек. Параметр необходимо указать вручную.
+
* Сохранить текущий `appsettings.json`.
** Все выполненные настройки останутся без изменений, стандартный файл конфигурации будет сохранён как `appsettings.json.dpkg-dist` (`appsettings.json.rpmnew` для {os3}).
* Показать различия между версиями.
** В окне командной строки будут отображены отличия между старой и новой версией. Знаком `+` обозначаются добавленные строки, знаком `-` -- удалённые.
* Запустить оболочку командной строки для проверки ситуации.
** Возвращает в окно командной строки, дальнейшие действия зависят от администратора.
====
endif::[]
// end::main-update-process[]
+
. Запустите _{mc}_ и перейдите в раздел menu:Серверы[Имя-сервера > Сервер приложений > Базы данных].
+
****
Пользователь, от имени которого запускается _{mc}_ должен являться администратором {of-mc} -- быть добавленным в группу _{dv-web-admin-cns-admins-serv}_ в конфигурационном файле {of-mc}, см. раздел "xref:dev@mgmtconsole:admin:config.adoc[]".
// * Входить в группы {dv} в Справочнике сотрудников:
// +
// - _{dv-dm-admins-dir}_.
// - _{dv-ad-admins-dir}_.
// - _{dv-sys-wf-dir}_.
// - __Системные группы_.
****
+
ifndef::solmgr[]
. Обновите существующую БД по инструкции, приведённой в документации модуля _{mc}_, раздел "xref:dev@mgmtconsole:servers:db-update.adoc[]".
ifndef::nolibs[]
+
. Дойдите до выбора обновляемых библиотек карточек. Выберите библиотеки и нажмите *Далее*.
+
.Обновление библиотек карточек
image::dev@mgmtconsole:servers:db-update-libs.png[Обновление библиотек карточек]
+
. Перезапустите службу Сервера {dv} на Linux ещё раз.
. Выберите модули {dv}, настройки которых должны быть загружены в БД и нажмите *Загрузить*.
endif::nolibs[]
+
.Шаг загрузки настроек модулей
image::dev@mgmtconsole:servers:db-update-solutions.png[Шаг загрузки настроек модулей]
endif::solmgr[]
