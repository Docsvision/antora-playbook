= Настроить кэш-сервер Redis

Важным условием для корректной работы системы, включающей несколько процессов сервера {dv}, является использование всеми процессами общего серверного кэша. Рассинхронизация кэша может стать причиной появления неактуальных данных и других ошибок. В качестве хранилища распределенного кэша в {dv} выступает кэш-сервер Redis.

{dv} поддерживает работу с Redis версии {redis-v}, совместимость с более поздними версиями не гарантируется.

[WARNING]
====
Для работы с Redis лицензия {dv} должна содержать опцию _{dv} кэш-сервер Redis_. Отсутствие лицензии приведёт к ошибке в работе сервера {dv}.

Кэш-сервер Redis не поддерживает работу в ОС Microsoft Windows.
====

Системные требования Redis зависят от желаемой производительности и должны рассчитываться индивидуально для используемой ОС. Описание требований выходит за рамки документации {dv}, как и инструкция по установке.

Официальная документация Redis может быть получена из интернет-архива:

* https://web.archive.org/web/20241007143629/https://redis.io/docs/latest/operate/oss_and_stack/management/optimization/benchmarks/[Ориентиры производительности]
* https://web.archive.org/web/20240318121627/https://docs.redis.com/latest/rs/installing-upgrading/install/plan-deployment/hardware-requirements/[Технические требования]
* https://web.archive.org/web/20231216171806/https://redis.io/docs/getting-started/installation/[Инструкция по установке]

[#requirements]
== Требования к настройке Redis

После установки Redis измените настройки в конфигурационном файле `redis.conf`.

. Отключите сохранение резервных копий данных на диск, закомментировав следующие строки:
+
[source]
----
save 900 1
save 300 10
save 60 10000
----
+
. Затем установите значение параметра `appendonly` в *no* (по умолчанию).
. Измените политику перезаписи данных при нехватке памяти на `allkeys-lru` (удаление наименее используемых данных):
+
[source]
----
maxmemory-policy allkeys-lru
----
+
. Чтобы избежать ошибок при подключении, привяжите адрес в конфигурационном файле Redis:
+
 sudo nano /etc/redis/redis.conf
+
В конце строки `bind 127.0.0.1 ::1` укажите корректный адрес кэш-сервера.
+
. Перезапустите Redis:
+
 sudo systemctl restart redis-server.service
+
. Подключение должно работать корректно. Проверить, что сервер обращается к нужному адресу можно следующей командой:
+
 ss -tunlp | grep :6379

[#connection]
=== Подключение Redis к {dv}

При выборе провайдера "Redis" в группе настроек "xref:db-performance.adoc[]" становятся доступными следующие поля:

Строка подключения::
В поле указывается строка подключения к Redis.
+
[NOTE]
====
Пример настройки подключения к Redis приведён в разделе xref:db-redis-cache.adoc[].
====

Пароль::
Пароль для доступа к Redis. Требуется заполнять только в том случае, если настроена аутентификация при помощи пароля. При изменении адреса в "Строке подключения", пароль будет сброшен, потребуется ввести пароль заново.

Тест::
При нажатии кнопки выполняется проверка подключения на стороне сервера {dv}. Если не заполнена строка подключения, кнопка неактивна.

.Настройка подключения к серверу Redis
image::db-redis-cache.png[Настройка подключения к серверу Redis]

.Чтобы настроить подключение к серверу Redis:
. Перейдите в раздел настроек menu:Серверы[Имя-сервера > Сервер приложений > Базы данных].
. В таблице нажмите на строку настраиваемой базы данных, при работе с которой сервер будет кэшировать данные в Redis.
. В группе настроек "Производительность", в пункте "Настройки провайдера" выберите из раскрывающегося списка значение *_Redis_*. Будет разблокировано поле _Строка подключения_.
. Введите в поле _Строка подключения_ адрес и порт для подключения к компьютеру с Redis в формате `адрес:Порт`. По умолчанию Redis использует порт `6379`.
+
WARNING: Сетевые политики должны разрешать подключения с серверов {dv} к Redis.
+
. Нажмите кнопку *Тест*, чтобы проверить соединение с Redis, при возникновении ошибки подробности будут отображены на странице настроек.
. Сохраните изменения настроек базы данных.
. Если настраивается кластер серверов {dv}, подключите все сервера к одному кэш-серверу Redis.
