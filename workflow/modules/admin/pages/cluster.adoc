= Настройка кластера модуля {wf}

[#top]
С целью распределения нагрузки, обработка бизнес-процессов может быть распределена между экземплярами СУБП, запущенными на нескольких компьютерах.

Для каждого экземпляра СУБП назначается доля обрабатываемых процессов, определяющая процент его загрузки в кластере. Например, если для одного сервиса указана доля `3`, а второго -- `4`, то количество обрабатываемых каждым сервисом процессов будет соотноситься как `3:4`. То есть приблизительно `43%` процессов будет обрабатывать первый сервис, `57%` -- второй.

С целью распределения нагрузки обработка бизнес-процессов может быть распределена между экземплярами модуля {wf}, запущенными на нескольких компьютерах. Для каждого экземпляра назначается доля обрабатываемых процессов, определяющая его относительную нагрузку в кластере. Если один из экземпляров службы не запущен, обработку его доли БП осуществляют другие активные экземпляры службы.

[#install]
== Установка и настройка кластера модуля {wf}

Кластеризация модуля (создание кластера) рекомендуется в случаях, когда число одновременно работающих БП в системе {dv} превышает 5000 экземпляров, исходя из примерного расчета: 1 экземпляр модуля на каждые 5000 активных БП.

.Обязательные условия для работы кластера модуля {wf}:
* На всех узлах кластера должна быть установлена одинаковая версия модуля _{wf}_. Обновления и исправления модуля должны устанавливаться на все узлы кластера.
* На всех узлах кластера должен быть установлен одинаковый набор _Шлюзов_.
* Если для подписания и шифрования в БП используется сертификат, он должен быть установлен на всех узлах кластера. Личный ключ сертификата должен быть установлен в локальное хранилище на каждом узле. Сертификат и его ключи должны быть доступны для каждой учётной записи службы модуля {wf} в кластере.
* Дополнительные узлы предъявляют собственные xref:ROOT:requirements-separate.adoc[требования к системе].

.Чтобы настроить кластер модуля {wf}:
. Установите и настройте модуль {wf} на первом узле кластера согласно xref:install.adoc[инструкции].
. На втором узле кластера по аналогии установите модуль {wf}, а также другие необходимые модули, список которых перечислен в разделе "xref:ROOT:requirements-separate.adoc[Требования отдельной установки СУБП]".
. {blank}
+
[subs="specialchars,attributes,quotes"]
У второго экземпляра модуля {wf} заполните настройки в конфигурационном файле {config}.
+
[source,json]
----
{
  "Docsvision": {
    "ServiceId": "00000000-0000-0000-0000-000000000000", <.>
    "SettingsService": {
      "ConnectionString": "http://settings.domain.com:5200/api", <.>
      "ApiKey": "anything" <.>
    }
  }
}
----
<.> `ServiceId` -- Уникальный идентификатор данного экземпляра модуля, генерируется и записывается автоматически. Не копируйте идентификатор первого экземпляра модуля {wf}.
<.> `ConnectionString` -- Адрес подключения к {to-sett-serv}, который должен совпадать с тем, что указан в конфигурационном файле первого экземпляра модуля {wf}.
<.> `ApiKey` -- Ключ доступа к {to-sett-serv} -- "пароль", который должен совпадать с тем, что указан в конфигурационном файле первого экземпляра модуля {wf}.
. Перезапустите службу модуля {wf} на втором узле кластера.
. Откройте {mc} и убедитесь, что на странице menu:Серверы[Имя сервера > "xref:6.2@mgmtconsole:servers:workflow.adoc[{wf}]"] отобразился второй узел модуля {wf}.
. Для второго узла модуля {wf} в группе настроек "xref:6.2@mgmtconsole:servers:workflow-connection.adoc[Подключение]" укажите сервер приложений, почтовые соединения и системную учётную запись {dv}, которые указаны в настройках первого узла модуля {wf}.
. Для каждой обрабатываемой БД настройте "xref:6.2@mgmtconsole:servers:workflow-connection.adoc#handling[Долю процессов]" на обоих узлах кластера.
+
Чтобы поровну распределить нагрузку между двумя узлами кластера, установите одинаковое значение (например, `1`) в доле процессов у обоих узлов. Чтобы снять нагрузку с определённого узла кластера, установите значение `0` в его доле процессов. Допустимые значения -- от `0` до `1000`.
+
Например, если для одного узла указана доля `3`, а для второго -- `4`, то количество обрабатываемых каждым узлом процессов будет соотноситься как `3:4`. То есть приблизительно `43%` процессов будет обрабатывать первый узел, `57%` -- второй.
. Примените настройки модуля {wf} в {of-mc} и перезапустите службу модуля {wf}.

[#decluster]
== Удаление экземпляра модуля {wf} из кластера

Для корректного удаления экземпляра модуля {wf} из кластера выполните следующие действия:

. Остановите службу модуля {wf} на удаляемом узле.
. В {of-mc} в разделе "xref:6.2@mgmtconsole:servers:index.adoc[Серверы]" удалите компонент модуля {wf} с выбранного сервера.
. На компьютере, на котором установлен дополнительный экземпляр модуля {wf}, удалите его согласно xref:install.adoc#uninstall[инструкции].
