= Как развернуть документацию из исходного кода

Новая документация {dv} разворачивается с помощью https://docs.antora.org/[генератора статических сайтов Antora]. Для первой сборки сайта потребуется доступ к репозиториям документации {dv}, https://github.com/Docsvision?q=antora-&type=all&language=&sort=[расположенным на GitHub]. Репозитории документации обозначены префиксом `antora-`. Полный список источников указан в файле `https://github.com/Docsvision/antora-playbook/blob/083db793049a159db9b4c526ce5b1f3a58870c39/antora-playbook.yml#L24[antora-playbook.yml]` репозитория antora-playbook.

Документация может быть развёрнута локально, в таком случае адрес документации может быть изменён.

[#build-site]
== Сборка сайта

.Требования для сборки сайта:
* Установлен git.
* Установлен Node.js версии, указанной в разделе "https://docs.antora.org/antora/latest/install/windows-requirements/[Требования]" на сайте документации Antora.
* Доступ к сайту Github или иной доступ к репозиториям исходного кода документации.
* Доступ к локальной копии репозитория https://github.com/Docsvision/antora-playbook/[Docsvision/antora-playbook/].

. Откройте командную строку с расположением в корне репозитория "Docsvision/antora-playbook/"
. Установите Antora командой:
+
 npm i
+
. Запустите сборку сайта при помощи Antora, выполнив следующую команду:
+
 npx antora antora-playbook.yml
+
. Файлы сайта будут расположены в папке `wwwroot`. Для проверки расширения без замены существующего сайта задайте отдельный каталог результата через `ANTORA_BUILD_OUTPUT`, как описано в <<partial-build>>. Точный путь выводится в журнале и сохраняется в `build/partial-build/latest.json`.

[#view]
== Просмотр сайта

.Сайт можно просматривать:
** Локально -- нажмите на сгенерированные html-файлы, расположенные в папке `wwwroot`.
** С простого http-сервера -- выполните шаги, https://docs.antora.org/antora/latest/preview-site/#run-a-local-server-optional[указанные в инструкции Antora].

[#limitations]
== Ограничения

.После сборки сайта некоторые функции окажутся недоступны:
* Поиск по сайту.
* Просмотр страниц накопительных обновлений.

Чтобы воспользоваться функциями локального (офлайн) поиска, рекомендуется использовать расширение Antora Lunr Search. Подробная инструкция по разворачиванию приведена https://www.npmjs.com/package/antora-lunr[по ссылке].

[#dev]
== Инструкция для разработчиков документации

При запуске Antora исходные документы будут автоматически получены из репозиториев Docsvision на GitHub (все репозитории с приставкой -Antora).

Если вы хотите изменить исходный код документации, необходимо скопировать содержимое каждого репозитория, указанного в файле `antora-playbook.yml`:

[source,yml]
----
content:
  branches: 'dev'
  edit_url: ~
  sources:
    - url: https://github.com/Docsvision/System-Antora.git
----

Замените значение ключа `url` на собственную ссылку или локальное хранилище. См. подробнее в документации Antora: https://docs.antora.org/antora/latest/content-source-repositories/[Repositories and Content Source Roots] и https://docs.antora.org/antora/latest/playbook/content-source-url[URLs for Content Sources], в частности подпункт https://docs.antora.org/antora/latest/playbook/content-source-url/#local-urls[URLs for Content Sources | Use local content repositories].

****
Чтобы подробнее разобраться в синтаксисе AsciiDoc, прочитайте материалы на сайте https://docs.asciidoctor.org/asciidoc/latest/[docs.asciidoctor.org].

Также подробнее ознакомьтесь с https://docs.antora.org/[документацией Antora], чтобы лучше понимать, как создаётся сайт с документацией Docsvision.
****

Для работы с файлами AsciiDoc рекомендуется использовать ПО Jetbrains https://www.jetbrains.com/idea/download/#section=windows[IntelliJ Idea] с https://intellij-asciidoc-plugin.ahus1.de/docs/users-guide/index.html[плагином AsciiDoc].

[#partial-build]
== Полная и частичная сборка

Расширение `lib/partial-build.js` работает с Antora 3.2 и источниками, заданными в `content.sources`. Оно загружает все исходники из Git, включая исходники для межкомпонентных включений. Частичный режим сокращает преобразование страниц в HTML; получение исходников и чтение заголовков выполняются для всего набора.

Входные данные документации читаются только из коммитов выбранных веток и тегов. Изменения рабочего дерева, индекса и неотслеживаемые файлы не участвуют в сборке. Перед проверкой правок документации их необходимо закоммитить. Сам плейбук и расширение запускаются из текущего рабочего каталога.

Компоненты могут находиться в разных репозиториях или каталогах одного репозитория. Их расположение задаётся в плейбуке, в том числе через `start_path` или `start_paths`. Ручной список зависимостей включений не требуется.

=== Выбор режима

Переменные задаются в PowerShell перед запуском обычной команды сборки.

[cols="1,3",options="header"]
|===
|Переменная |Назначение
|`ANTORA_BUILD_MODE` |`full` -- полная сборка; `partial` -- строго частичная; `auto` -- частичная с переходом к полной, если сохранение остальных страниц нельзя подтвердить. По умолчанию используется `full`. Пустое или неизвестное значение является ошибкой.
|`ANTORA_BUILD_TARGETS` |Для `partial` и `auto` обязателен список `версия@компонент` через запятую. Для безверсионного компонента вместо версии указывается `_`. Повторяющиеся, пустые и неизвестные цели являются ошибкой. В режиме `full` переменную нужно убрать.
|`ANTORA_BUILD_BASELINE` |Каталог предыдущего проверенного результата. Если переменная отсутствует, используется каталог из `build/partial-build/latest.json`. Обычного `site-manifest.json` недостаточно: нужен также снимок `.partial-build/state.json` и все файлы базового сайта.
|`ANTORA_BUILD_OUTPUT` |Необязательный путь нового каталога для проверки внутри `build` данного плейбука. Каталог не должен существовать, совпадать с базовым сайтом или находиться внутри него. Без переменной результат заменяет каталог `output.dir` обычного плейбука, в данном случае `wwwroot`, после успешной сборки.
|===

.Первоначальная полная сборка
[source,powershell]
----
$env:ANTORA_BUILD_MODE = 'full'
Remove-Item Env:ANTORA_BUILD_TARGETS -ErrorAction SilentlyContinue
$env:ANTORA_BUILD_OUTPUT = 'build/check-full'
npx antora antora-playbook.yml
----

.Частичная сборка AI 6.1
[source,powershell]
----
$env:ANTORA_BUILD_MODE = 'partial'
$env:ANTORA_BUILD_TARGETS = '6.1@ai-module'
$env:ANTORA_BUILD_OUTPUT = 'build/check-ai'
npx antora antora-playbook.yml
----

.Несколько версий компонентов с автоматическим выбором объёма
[source,powershell]
----
$env:ANTORA_BUILD_MODE = 'auto'
$env:ANTORA_BUILD_TARGETS = '6.1@ai-module,6.1@platform'
$env:ANTORA_BUILD_OUTPUT = 'build/check-ai-platform'
npx antora antora-playbook.yml
----

В примерах используются отдельные каталоги проверки, которые ещё не должны существовать. Для повторной проверки выберите новые имена каталогов. Для обычной сборки в `output.dir` уберите `ANTORA_BUILD_OUTPUT` командой `Remove-Item Env:ANTORA_BUILD_OUTPUT -ErrorAction SilentlyContinue`.

Расширение сообщает запрошенный и фактический режим, причину перехода к полной сборке, число преобразованных страниц и каталог результата. Полная сборка обрабатывает все источники обычного плейбука; список целей в режиме `auto` не ограничивает полную сборку.

=== Навигация и зависимости

В частичном режиме новое дерево навигации каждой выбранной версии заменяет её дерево в снимке предыдущего сайта. Деревья остальных версий сохраняются. Поэтому в существующую версию можно добавлять страницы и пункты навигации без обязательной полной сборки.

Снимок содержит SHA источников, отпечатки исходных файлов, параметры компонентов и навигацию. Проверяется содержимое Git-коммитов, а не только имена веток. Изменения вне выбранных версий требуют полной сборки.

Во время обработки AsciiDoc расширение запоминает фактически разрешённые включения, в том числе вложенные и с подстановкой атрибутов. Для частичной сборки проверяются обратные зависимости из предыдущего снимка. Если изменённый фрагмент используется за пределами выбранных версий, частичная сборка отклоняется. Проверка консервативна: неразрешённые включения за пределами выбранного набора, например отсутствующее необязательное включение, требуют полной сборки при изменении исходников. Это не автоматический минимальный выбор всех затронутых страниц.

Полная сборка также требуется при добавлении компонента или версии, изменении параметров компонента, статуса предварительной версии, последней версии, заголовков и метаданных существующих страниц, удалении или переименовании ресурсов, изменении общих настроек, UI или расширений. В режиме `partial` выводится ошибка; в режиме `auto` выполняется полная сборка с объяснением причины. Отсутствующий или повреждённый базовый снимок обрабатывается аналогично. Неизвестная цель является ошибкой в обоих режимах.

=== Результат и проверка

Каждый запуск сначала готовит полный локальный сайт в отдельном каталоге. В частичном режиме файлы проверенного базового сайта копируются в новый каталог, затем заменяются выбранные страницы, их ресурсы и общие файлы, включая навигацию и манифест. Полная сборка создаёт сайт с нуля, поэтому удалённые ресурсы из прежнего результата в него не попадают. Без `ANTORA_BUILD_OUTPUT` готовый результат заменяет `output.dir`, а прежний каталог сохраняется в `build/partial-build/backups`. При заданном `ANTORA_BUILD_OUTPUT` существующий сайт не заменяется.

Файл `partial-build-report.json` содержит режимы, причины перехода к полной сборке, SHA источников, счётчики и длительность этапов. Снимок `.partial-build/state.json` содержит также контрольные суммы выходных файлов и полное время завершённой сборки. Только после успешной сборки обновляется указатель `build/partial-build/latest.json`. При ошибках Antora новый результат не становится базовым сайтом.

Результат предназначен для замены сайта целиком. Нельзя накладывать полный результат поверх прежнего сайта без удаления устаревших файлов на стороне развёртывания. Само расширение ничего на сервер не отправляет. Снимок `.partial-build` нужно сохранять как артефакт сборки; публиковать его в открытом доступе не требуется.

Ненужные каталоги проверки и резервные копии следует удалять отдельно. Для контроля UI используется локальный архив `ui.bundle.url`; удалённый UI-архив в этой реализации не поддерживается. Изменение условий, которые не представлены исходниками, плейбуком или контролируемыми ресурсами, требует явной полной сборки.

Одновременные запуски блокируются файлом `build/partial-build/build.lock`. При обычном завершении он удаляется автоматически. После аварийного завершения сначала убедитесь, что предыдущий процесс Antora остановлен, затем удалите оставшийся файл блокировки вручную и повторите запуск.

Проверки логики расширения в используемой среде Node.js 24 запускаются командой:

[source,powershell]
----
node --test --test-isolation=none lib/partial-build.test.js
----
