= Подключение к {dv} по HTTPS

[CAUTION]
====
{dv} не поддерживает безопасную работу по HTTP, поэтому настройка HTTPS является обязательной даже в закрытых контурах.

При работе по HTTP легко реализуема атака MiTM, в результате которой могут быть компрометированы учетные данные, перехвачена сессия и раскрыта вся передаваемая по сети информация.
====

См. также "xref:new-admin-console@engineer:ROOT:tls-settings.adoc[]".

Модули и сервисы {dv}, работающие по сети (например, Сервер приложений, {wc}, {wf} и {mc} и другие) по умолчанию не используют HTTPS, защищённое соединение необходимо настраивать после установки системы. Для безопасного подключения необходим сертификат, который можно приобрести в одном из удостоверяющих центров либо <<certificate,сгенерировать самоподписанный сертификат>>. В зависимости от операционной системы способ установки сертификата отличается. Для Linux сертификат устанавливается в папку, а для Windows -- в хранилище.

После установки системы и получения сертификата требуется настроить доступ к {dv} по HTTPS. Настройка выполняется в конфигурационных файлах модулей системы. В первую очередь потребуется отредактировать конфигурационный файл модуля {pl} по адресу `/usr/lib/docsvision/platform/appsettings.json` для Linux и `C:\Program Files\Docsvision\Platform\appsettings.json` для Windows.

После изменения конфигурации модуля {pl} аналогичным образом отредактируйте конфигурационные файлы модулей {wc}, {wf} и {mc}.

[tabs]
=====
Конфигурация для Linux::
+
.Фрагмент конфигурационного файла:
[source,json]
----
{
  "AllowedHosts": "*",
  "Kestrel": {
    "Endpoints": {
      "Https": {
        "Url": "https://*:5020", <.>
        "Certificate": {
          "Path": "/folder/certificate.crt", <.>
          "KeyPath": "/folder/docsvision.key" <.>
        }
      }
    }
  }
}
----
<.> `Url` -- адрес и порт для доступа по HTTPS. При такой конфигурации сервис будет прослшуивать одновременно два порта: стандартный `5000` для HTTP и `5020` для HTTPS. Чтобы использовать стандартный порт `5000` для подключения по HTTPS, измените параметры следующим образом: menu:Http[Url > "https://*:5000"]. Обратите внимание, вместо `Https` в данной конфигурации указывается `Http`.
<.> `Path` -- папка, в которую установлен полученный или <<certificate,самоподписанный>> сертификата.
<.> `KeyPath` -- папка, в которой расположен ключ шифрования полученного или <<certificate,самоподписанного>> сертификата.

Конфигурация для Windows::
+
.Фрагмент конфигурационного файла:
[source,json]
----
{
  "AllowedHosts": "*",
  "Kestrel": {
    "Endpoints": {
      "HttpsInlineCertStore": {
        "Url": "https://my-site.com:443", <.>
        "Certificate": {
          "Subject": "my-site.com", <.>
          "Store": "My", <.>
          "Location": "CurrentUser", <.>
          "AllowInvalid": false <.>
        }
      }
    }
  }
}
----
<.> `Url` -- адрес и порт для доступа по HTTPS. При такой конфигурации сервис будет прослшуивать одновременно два порта: стандартный `5000` для HTTP и `5020` для HTTPS. Чтобы использовать стандартный порт `5000` для подключения по HTTPS, измените параметры следующим образом: menu:Http[Url > "https://*:5000"]. Обратите внимание, вместо `Https` в данной конфигурации указывается `Http`.
<.> `Subject` -- адрес сайта, переданный в параметре `DnsName` при создании сертификата.
<.> `Store` -- наименование хранилища, переданное в параметре `CertStoreLocation` при создании сертификата.
<.> `Location` -- хранилище сертификата, переданное в параметре `CertStoreLocation` при создании сертификата.
<.> `AllowInvalid` -- стоит ли считать недействительные сертификаты самоподписанными (по умолчанию `false`).

=====

WARNING: После редактирования конфигурационных файлов обязательно перезапустите службы модулей!

Если настройки выполнены корректно, система {dv} должна работать без ошибок, обновление БД также должно проходить без ошибок.

[#client]
== Клиентская часть

После настройки защищённого подключения для сервера необходимо выполнить настройки для клиентской стороны.

. В первую очередь потребуется в конфигурационном файле {wc}а изменить адрес подключения к серверу {dv} в параметре `ConnectionAddress`, указав в нём адрес с `https`.
. Изменить адрес подключения с `http` на `https` потребуется в параметре `Urls` для всех остальных web-сервисов, включая: {sm}, {sett-serv}. А также в параметре `Url` конфигурационного файла `appsettings.json` модуля Служба {ws}. При наличии других модулей убедитесь, что их конфигурация соответствует требованиям.
. Если используется самоподписанный сертификат, необходимо указать адрес Storage Server с `https` в конфигурационном файле `windows-client-part.json` в параметрах `ConnectAddress` и `ServerUrl`. Подробнее см. "xref:new-admin-console@platform:console:manage-access.adoc[]" в документации модуля {pl}. Также потребуется добавить сертификат в доверенные корневые сертификаты на:
+
* Серверах {wc}а, Службы {ws}, модуля {wf}, {of-mc}, {of-sm}.
* Рабочих местах пользователей {wc}а.
* Рабочих местах пользователей {wincl}а.
+
. Если доступ по HTTPS настраивается для {of-sett-serv}, также потребуется изменить параметр menu:SettingsService[ConnectionString] в конфигурационных файлах:
+
* {wc}а, модуля {wf}, Сервера приложений (модуля {pl}), {of-mc}, {of-fs}, {of-sm}.

[#cert-linux]
=== Создание сертификата в Linux

// tag::certificate[]
. Установите пакет `openssl` командой:
+
[tabs]
====
{os1}::
+
 $ sudo apt-get install openssl

{os2}::
+
 $ sudo dnf install openssl
====
+
. [[before]]Создайте самоподписанный сертификат SSL.
+
--
 $ openssl req -x509 -newkey rsa:2048 -keyout docsvision.key -nodes -out certificate.crt -subj "/CN=example.company.com" <.>

<.> Замените `docsvision.key` и `certificate.crt` на собственные названия для ключа и сертификата, вместо `/CN=example.company.com` укажите адрес сервера {dv} на Linux, например, `/CN=help.docsvision.com`.
--
+
NOTE: Подробный пример создания сертификата приведён в руководстве по настройке системы, раздел "xref:new-admin-console@engineer:ROOT:create-cert.adoc[]".
+
. Добавьте сертификат в доверенные, скопировав его в директорию `/usr/local/share/ca-certificates/`.
. Обновите список доверенных сертификатов:
+
[tabs]
====
{os1}::
+
 $ sudo update-ca-certificates

{os2}::
+
 $ sudo update-ca-trust
====

[#cert-windows]
=== Создание сертификата в Windows

. В ОС Windows самоподписанный сертификат можно сгенерировать следующей командой в PowerShell:
+
[source,powershell]
----
New-SelfSignedCertificate -CertStoreLocation cert:\currentuser\my -DnsName "example.company.com" -FriendlyName "Docsvision Site" -KeyUsage "DigitalSignature", "KeyEncipherment" -KeyAlgorithm RSA  -KeyLength 2048 -NotAfter $([datetime]::now.AddDays(90))
----
+
.Расшифровка команды:
* `cert:\currentuser\my` -- место установки сертификата
* `example.company.com` -- адрес сайта
* `{dv} Site` -- название сайта
* `RSA` -- алгоритм шифрования
* `2048` -- длина ключа.
* `$([datetime]::now.AddDays(90))` -- срок действия сертификата (90 дней). Рекомендуется устанавливать от 90 до 360 дней.
+
. Сертификат появится в хранилище _Личное_ среди сертификатов пользователя, из которого его можно экспортировать в файл. Выберите сертификат из списка двойным нажатием мыши, откройте вкладку "Состав".
+
.Просмотр сертификата на вкладке "Состав"
image::new-admin-console@engineer:ROOT:certificate-check.png[Просмотр сертификата на вкладке "Состав"]
+
. Экспортируйте сертификат, нажав кнопку *Копировать в файл* и проследуйте инструкциям мастера экспорта сертификатов.
. Установите экспортированный сертификат в хранилище "Доверенные корневые сертификаты" на сервере, а также на машинах пользователей. Для этого откройте файл сертификата и нажмите кнопку *Установить сертификат*.
+
.Сертификат готов к установке
image::new-admin-console@engineer:ROOT:certificate-install.png[Сертификат готов к установке]
// end::certificate[]
. Выполните настройку доступа к {dv} по HTTPS.
