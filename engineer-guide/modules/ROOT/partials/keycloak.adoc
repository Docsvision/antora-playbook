[#keycloak]
== Регистрация расширения Keycloak

[NOTE]
====
* Для работы расширения авторизации Keycloak требуется опция лицензии _{dv} Коннектор к Keycloak_.
* Авторизация с помощью Keycloak поддерживается в {wc}е {cu252-wc-req} при установке модуля {pl} {cu252-pl-req}.
====

[source,json]
----
{
  "Docsvision": {
    "Platform": {
      "Server": {
        "Authentication": {
          "Extensions": {
		    "Keycloak": {
              "Name": "Keycloak", <.>
              "TypeName": "DocsVision.Platform.Authentication.Keycloak.KeycloakRootAuthenticationExtension, DocsVision.Platform.Authentication.Keycloak, Version=6.0.0.0, Culture=neutral, PublicKeyToken=7148AFE997F90519", <.>
              "Settings": "<?xml version=\"1.0\" encoding=\"utf-16\"?><KeycloakAuthenticationSettings  xmlns:xsd=\"http://www.w3.org/2001/XMLSchema\" xmlns:xsi=\"http://www.w3.org/2001/XMLSchema-instance\"><WellKnownConfigurationUrl>https://example.domain.com/realms/testDv/.well-known/openid-configuration</WellKnownConfigurationUrl><ClientId>test</ClientId><Secret>JwIcDLOLEATB2R69bZac9BMHpzC8Px0P</Secret><AccountNameClaim>http://schemas.xmlsoap.org/ws/2005/05/identity/claims/emailaddress</AccountNameClaim><UniqueIdClaim>DocsvisionID</UniqueIdClaim><ScopesSupported>openid email</ScopesSupported></KeycloakAuthenticationSettings>", <.>
              "Id": "{735EE1ED-F0D1-4D1B-90B0-B48D73BF49C0}" <.>
            }
          },
          "Tenants": { <.>
            "CurrentDB": {
              "Extensions": "{735EE1ED-F0D1-4D1B-90B0-B48D73BF49C0}", <.>
              "Name": "CurrentDB" <.>
            }
          }
        }
      }
    }
  }
}
----
<.> `Name` -- задаёт отображаемое имя сервиса аутентификации в справочнике сотрудников.
<.> `TypeName` -- строка с именем типа, реализующего расширение.
<.> `Settings` -- строка настроек расширения, для Keycloak. Подробнее см. <<keycloak-settings,ниже>>.
<.> `ID` -- строка с идентификатором расширения в виде Guid.
<.> `Tenants` -- в параметре указываются расширения аутентификации для конкретных БД {dv}.
<.> `Extensions` -- строка, содержащая идентификаторы расширений аутентификации для конкретной БД в виде списка Guid через `;` (точка с запятой).
<.> `Name` -- строка, содержащая псевдоним БД, например: `CurrentDB`.

[#keycloak-settings]
=== Строка настроек Keycloak

NOTE: Для работы расширения авторизации Keycloak требуется опция лицензии _{dv} Коннектор к Keycloak_.

include::partial$excerpts.adoc[tags=pretty]

[source,xml]
----
<?xml version=\"1.0\" encoding=\"utf-16\"?>
  <KeycloakAuthenticationSettings
    xmlns:xsd=\"http://www.w3.org/2001/XMLSchema\"
    xmlns:xsi=\"http://www.w3.org/2001/XMLSchema-instance\">
    <WellKnownConfigurationUrl>https://example.domain.com/realms/testDv/.well-known/openid-configuration</WellKnownConfigurationUrl> <.>
    <ClientId>test</ClientId> <.>
    <Secret>JwIcDLOLEATB2R69bZac9BMHpzC8Px0P</Secret> <.>
    <AccountNameClaim>http://schemas.xmlsoap.org/ws/2005/05/identity/claims/emailaddress</AccountNameClaim> <.>
    <UniqueIdClaim>DocsvisionID</UniqueIdClaim> <.>
    <ScopesSupported>openid email</ScopesSupported> <.>
</KeycloakAuthenticationSettings>
----
<.> `WellKnownConfigurationUrl` -- URL публичной конфигурации OpenID.
<.> `ClientId` -- идентификатор тенанта Keycloak в котором производится привязка пользователей.
<.> `Secret` -- секрет приложения, настроенного для аутентификации пользователей.
<.> `AccountNameClaim` -- имя поля в токене, значение которого используется в качестве логина. Указывается имя поля, а не логин конкретного пользователя.
<.> `UniqueIdClaim` -- имя поля в токене, значение которого используется в качестве неизменяемого уникального идентификатора пользователя. В примере используется поле `DocsvisionID`. Для такой настройки необходимо создать соответствующий атрибут пользователя в Keycloak, заполнить его и настроить передачу в токен. Если идентификатор передаётся в другом поле, укажите имя этого поля.
<.> `ScopesSupported` -- при загрузке расширения список областей доступа берется из конфигурации KeyCloak, указанной в параметре `WellKnownConfigurationUrl`. Если есть необходимость переопределить список областей доступа, передаваемых в запросе, можно добавить секцию `ScopesSupported` и в неё через пробел указать необходимые области для работы.
// end::keycloak[]

// tag::uri-1[]
При обработке токена имена некоторых стандартных полей автоматически преобразуются в URI. В `AccountNameClaim` и `UniqueIdClaim` необходимо указывать имена после преобразования.
// end::uri-1[]

Например, для получения логина из поля _email_ в `AccountNameClaim` укажите `http://schemas.xmlsoap.org/ws/2005/05/identity/claims/emailaddress`. Для получения уникального идентификатора из поля _sub_ в `UniqueIdClaim` укажите `http://schemas.xmlsoap.org/ws/2005/05/identity/claims/nameidentifier`.

// tag::uri-2[]
Имена полей, для которых преобразование не предусмотрено, указываются без изменений. Например, для поля `preferred_username` в `AccountNameClaim` указывается `preferred_username`.

Имена пользовательских полей, для которых преобразование не предусмотрено, указываются без изменений. Например, для `DocsvisionID` в `UniqueIdClaim` указывается `DocsvisionID`.
// end::uri-2[]

В параметры подставляются имена полей, а не их значения. Например, если поле `email` содержит адрес `user@example.com`, в `AccountNameClaim` указывается URI для поля _email_, а в качестве логина используется адрес `user@example.com`.
